대량 파일 이름 일괄 변경(Batch Rename) 완벽 가이드

최종 갱신: 2026년 9월 14일 읽는 시간: 약 10분 대상: 크리에이터, 소프트웨어 엔지니어, 데이터 관리자

현대 디지털 업무 환경에서 수백 개에서 수천 개에 달하는 파일 리소스를 다루는 일은 일상적입니다. 스마트폰이나 DSLR 카메라에서 촬영된 원시 사진 파일(IMG_20260901_001.JPG), 메신저나 이메일로 전달받은 업무 문서(기획서(1)_수정_최종(진짜).docx), 디자인 프로젝트에서 추출된 불규칙한 그래픽 에셋까지, 파일명이 체계적으로 정렬되어 있지 않으면 협업과 파일 검색에 막대한 비효율이 발생합니다.

과거에는 이러한 문제를 해결하기 위해 윈도우 탐색기에서 F2 키를 눌러 하나씩 바꾸거나, 파이썬(Python) 스크립트 혹은 윈도우 파워쉘(PowerShell) 명령어를 직접 작성해야 했습니다. 하지만 스크립트 작성 방식은 오타 하나로 원본 파일명이 영구적으로 유실될 수 있는 위험을 안고 있습니다. 본 가이드에서는 명령줄(CLI) 및 파이썬 대비 웹 브라우저 기반 파일 리네이밍의 보안 메커니즘, 실무 정규표현식 10선, 그리고 macOS-Windows 간 한글 자소 분리(NFD/NFC) 해결법을 완벽히 정리합니다.

1. 파일 처리 방식 심층 비교: CLI/파이썬 vs 웹 기반 리네이머

운영체제 명령어(PowerShell, Bash)나 파이썬 스크립트를 통한 대량 파일명 변경은 강력하지만, 실행 즉시 파일 시스템에 직접 덮어쓰기 때문에 '되돌리기(Undo)'가 불가능하며 비전공자가 다루기 어렵습니다. 반면 최신 WICG File System Access API 기반의 웹 리네이머는 브라우저 보안 샌드박스 내부에서 안전한 시각적 검증을 거친 후 사용자의 승인을 얻어 변경을 적용합니다.

비교 항목 Windows PowerShell (CLI) Python 스크립트 (CLI) Batcher Tools (웹 GUI)
설치 및 환경 준비 기본 내장 (단, 실행 정책 ExecutionPolicy 변경 필요) Python 인터프리터 및 가상환경 설치 필요 설치 불필요 (크롬/엣지 브라우저에서 즉시 실행)

실행 취소 (Undo / Reset) 불가 (되돌리기 스크립트를 미리 짜두지 않으면 복구 불가) 별도 로그 및 역연산 로직을 직접 구현해야 함 원클릭 Undo 및 원본 초기화(Reset) 완벽 지원

2. 실무에서 바로 복사해 쓰는 정규표현식(Regex) 실전 예제 10선

배처 툴의 '문자열 치환' 모드에서 정규식 옵션을 켜면, 캡처 그룹($1, $2)과 메타 문자를 조합하여 아무리 복잡한 규칙의 파일명도 클릭 한 번으로 손쉽게 재구성할 수 있습니다. 디자이너와 엔지니어가 실무에서 가장 자주 사용하는 10가지 검증된 패턴입니다.

# 정규식 검색 패턴 치환 문자열 검색 대상 예시 변경 후 결과 실무 활용 설명
1 ^([a-zA-Z]+)_(\d{4})(\d{2})(\d{2}) $2-$3-$4_$1 report_20260914.pdf 2026-09-14_report.pdf 문서명 뒤에 붙은 날짜를 맨 앞으로 이동하고 하이픈을 삽입하여 탐색기 시간순 정렬
2 \s+ _ my final design v1.png my_final_design_v1.png 웹 서버 및 리눅스 시스템에서 URL 인코딩 에러(%20)를 유발하는 공백을 언더스코어로 통일
3 \((.*?)\) [$1] icon(active).svg icon[active].svg 비표준 소괄호 태그를 대괄호 규격으로 일괄 치환하여 디자인 에셋 관리 통일
4 _+(?=\.) (빈 칸) banner_ad___.jpg banner_ad.jpg 텍스트 치환 과정에서 확장자 바로 앞에 중복으로 남은 불필요한 언더스코어 말끔히 제거
5 ^IMG_\d{4}\. Photo_ IMG_4921.jpg Photo_4921.jpg 스마트폰 및 디지털 카메라가 자동으로 부여한 무의미한 기본 접두사를 고유 프로젝트명으로 교체
6 [\s_]*[vV](\d+)\.(\d+) _v$1.$2 app V 2.1.zip app_v2.1.zip 제각각 작성된 버전 표기(공백, 대문자 V)를 정형화된 시맨틱 버전(_v2.1)으로 규격화
7 [^\w\-\.가-힣] _ 기획서#1!@.docx 기획서_1__.docx OS 간 전송 시 깨지거나 명령줄에서 에러를 일으키는 특수문자나 이모지를 안전한 기호로 정제
8 (?<=_)(draft|temp|copy)(?=_) (빈 칸) logo_draft_v1.png logo__v1.png 작업 도중 파일명 중간에 임시로 삽입되었던 작업 상태 태그를 완성본 단계에서 일괄 삭제
9 _([0-9]{3,4}x[0-9]{3,4}) @$1 hero_1920x1080.png hero@1920x1080.png 에셋 해상도 수치 구분자를 모바일 및 반응형 웹 표준 앳(@) 구분자로 전환
10 ^_+|_+$ (빈 칸) _header_image_.png header_image.png 문자열 삭제 후 파일명의 맨 앞이나 맨 뒤 끝부분에 고립되어 남은 언더스코어 일괄 정리
macOS와 Windows 간 한글 자소 분리(NFD vs NFC) 현상과 완전 해결법

발생 원인: 유니코드 정규화 표준의 차이
맥(macOS)의 APFS/HFS+ 파일 시스템은 한글 파일명을 저장할 때 초성, 중성, 종성을 낱 글자 단위로 분리하여 기록하는 NFD(Normalization Form Decomposition) 방식을 기본 사용합니다. 반면 윈도우(Windows)의 NTFS 파일 시스템은 하나의 완성된 글자로 결합하여 저장하는 NFC(Normalization Form Canonical Composition) 방식을 사용합니다.

실무에서 발생하는 치명적 문제:
맥 사용자가 작성한 파일을 윈도우 PC로 가져오면 파일명이 ㅂㅗㄱㅅㅏ.png 형태로 자소가 완전히 분리되어 깨져 보입니다. 이 상태의 파일은 윈도우 탐색기에서 한글 검색이 되지 않으며, 웹 서버나 데이터베이스에 업로드할 때 문자열 인코딩 불일치로 심각한 404 오류나 링크 깨짐을 유발합니다.

배처 툴의 자동 정규화 해결책:
자바스크립트 표준 API인 String.prototype.normalize('NFC')를 기반으로 작동하는 배처 툴은, 맥에서 생성된 자소 분리 파일을 브라우저로 드래그 앤 드롭하는 즉시 내부 엔진이 자동으로 감지하여 완벽한 완성형 한글(NFC)로 자동 재조합합니다. 복잡한 파이썬 스크립트나 터미널 명령어 없이 원클릭으로 수천 개의 자소 분리 파일을 정상 한글명으로 복구할 수 있습니다.

3. 실수 없는 대량 리네이밍을 위한 3단계 안전 워크플로우

대량 파일명 가공 시 가장 중요한 것은 작업자의 실수를 방어하는 복구 매커니즘입니다. 배처 툴은 작업 도중 발생할 수 있는 휴먼 에러를 완벽하게 차단하기 위해 다음 3단계 안전장치를 제공합니다.

  1. 실시간 인라인 프리뷰(Live Preview): 치환 규칙, 접두사, 일련번호 규칙을 타이핑하는 순간, 우측 대기열 테이블의 '변경될 이름' 열에 변경 결과가 1ms 단위로 즉시 렌더링됩니다. 실제 디스크에 쓰기 전에 결과를 눈으로 100% 검증할 수 있습니다.
  2. 무제한 실행 취소(Undo): 잘못된 정규식 패턴이나 잘못된 번호 규칙을 실수로 적용했더라도, 상단의 Undo 버튼을 클릭하면 직전 상태의 파일명으로 즉각 롤백됩니다.
  3. 초기화(Reset): 복잡한 규칙을 여러 번 중첩 적용하다가 처음 상태로 돌아가고 싶을 때, Reset 버튼 한 번으로 폴더를 처음 불러왔던 무결한 원본 상태로 즉시 복원합니다.

전문가 팁: 대량의 파일을 변경하기 전에 특정 파일만 선별하고 싶다면 상단의 '확장자 필터'에 .png, .jpg를 입력해 보세요. 하위 폴더 내의 무관한 시스템 파일은 제외하고 원하는 미디어만 안전하게 골라낼 수 있습니다.
